# Fly: working rules

A browser game: third-person arcade flight as a spirit bird over a Ghibli-style archipelago.
Fast, fluid flight; exploration with soft goals (light motes, golden feathers, shrines, wind currents).
**Feel is the whole game, and it lives in the flight model and the camera.**
Original design notes: `docs/design-starting-point.md` (a starting point, not a spec).

## Stack (pinned, do not drift)

- **three 0.184.0 (r184)**, `WebGLRenderer` (WebGL 2). Modern API only: `BufferGeometry`, no `THREE.Geometry`,
  nothing deprecated, named imports from `'three'` (no `import * as THREE`). Addons from `three/addons/...`.
- TypeScript (strict), Vite. `lil-gui` for the tuning panel. No other runtime dependencies.
- Assets are generated by **Blender 4.0 Python scripts** in `art/` (installed with `apt-get install blender
  python3-numpy`), exported as glTF into `public/models/`. Never hand-edit the `.glb`/`.json` outputs.
- Do not bump versions or add dependencies without asking. WebGPU is a later option, not now.

## Commands

- `npm run dev`: dev server with HMR. Dev pages: `/dev/creature.html` (creature lab: orbit, drive sliders,
  `?view=0,6,0.01&speed=65`) and `/dev/models.html?file=vegetation.glb&lod=0` (any model file, game shading).
- `npm run build`: typecheck + production build (must pass before every commit)
- `npm run typecheck`: `tsc --noEmit` only
- `npm run assets`: rebuild every model in `public/models/` from `art/*.py` (needs Blender)

## Architecture: one system per file

| File | Owns |
| --- | --- |
| `src/main.ts` | bootstrap, game states (title/playing/paused), fixed-timestep loop, settings, adaptive quality |
| `src/flight.ts` | arcade flight model: pitch/bank/yaw, speed, cruise thrust, boost, skim, currents, flap, energy |
| `src/camera.ts` | follow camera: per-axis springs relative to the bird's velocity, look-ahead, FOV, roll, shake |
| `src/input.ts` | keyboard + pointer-locked mouse (virtual stick) + gamepad → `FlightInput` |
| `src/creature.ts` | spirit bird: Blender parts assembled into a skeleton, procedural animation, rim light |
| `src/streamers.ts` | tail ribbon streamers, simulated as world-space chains |
| `src/map.ts` | **the curated world**: islands, landmarks, villages, props, boats, currents, mote trails, feathers, shrines, spawn |
| `src/heightfield.ts` | terrain height as a pure function (island profiles + cliffs + noise), `surface()` for collision |
| `src/terrain.ts` | terrain chunk meshes: streaming, LOD, skirts, smooth normals |
| `src/terrainShading.ts` | GLSL for the painted terrain look (meadows, forest canopy, strata cliffs, beaches, snow) |
| `src/terrainMaps.ts` + `terrainBake.worker.ts` | baked world maps (height, AO, sun shadow) in a worker |
| `src/shading.ts` | patches three's Lambert lighting: soft cel ramp, rim, per-fragment direct-light scale |
| `src/worldMaterial.ts` | shared material for trees, buildings, landmarks (baked light, cloud shadows, sway, fog scale) |
| `src/water.ts` | stylized sea: depth colors, shore foam, ripples, reflections, glints |
| `src/vegetation.ts` | trees, bushes, rocks: seeded placement on forest patches, instanced LODs, view-cone culling |
| `src/grass.ts` | GPU-instanced meadow grass around the camera, wind gusts, flowers, parted by the bird |
| `src/places.ts` | turns villages/props/landmarks/shrines from `map.ts` into placements on the terrain |
| `src/props.ts` | buildings, landmarks, boats: instancing, LOD, lit windows at dusk, sails, lighthouse beam |
| `src/obstacles.ts` | collision spheres for solid props; pushes the bird and camera out |
| `src/clouds.ts` + `cloudShadows.ts` | instanced cumulus (Blender), painted lighting, in-cloud test, moving cloud shadows |
| `src/currents.ts` | wind currents: streak visuals and the grab/pull/carry query |
| `src/collectibles.ts` | light motes, golden feathers, shrines: state, visuals, pickup, spark bursts |
| `src/progress.ts` | what pickups mean: energy, chimes, HUD messages, feather upgrades, hints, saving |
| `src/speedfx.ts` | speed lines and skim spray/leaves |
| `src/post.ts` | MSAA render target, bloom, tone mapping, grading, speed radial blur |
| `src/world.ts` | scene, lights, fog, real-time shadow box around the player |
| `src/atmosphere.ts` | time of day: sun direction and all sky/fog/light colors from `SKY_KEYS` |
| `src/fog.ts` | patches three's fog chunks: height falloff + sun tint; shared fog uniforms |
| `src/sky.ts` | sky dome: gradient, wisps, sun disc and glow, moon |
| `src/thermals.ts` | rising air columns (climb by circling), motes, circling birds |
| `src/audio.ts` | Web Audio bus, wind, rush, skim, flaps, pickup chimes, listener |
| `src/music.ts` / `src/soundscape.ts` | ambient pad / surf and positioned seabird calls |
| `src/models.ts` | glTF loading: named geometries out of `public/models/*.glb` |
| `src/textures.ts` | shared noise texture (with an identical CPU sampler) and particle dot |
| `src/noise.ts`, `src/random.ts`, `src/palette.ts` | seeded noise and PRNG; colors, terrain ramps, time-of-day keys |
| `src/ui/*` | HUD, menus, i18n (ES/EN), save data (localStorage), CSS |
| `src/tuning.ts` + `tuning-defaults.json` | tuning panel (G), slider ranges, persistence, defaults |
| `art/lib.py` | Blender helpers: metaballs, smoothing, decimate, tubes, flat hard-surface parts, AO bake, export |
| `art/vegetation.py`, `clouds.py`, `architecture.py`, `creature.py` | the asset generators |

Keep files focused. A new system gets a new file, not a new section in an existing one.

## Conventions

- Units: meters, seconds, radians internally (tuning values may be in degrees; suffix them `Deg`).
- World: sea level is y = 0, north is -Z. The archipelago fits in ±5 km (`WORLD_HALF_SIZE`); beyond is open sea.
- To place or reshape anything in the world, edit `map.ts`. Noise only adds detail around authored shapes.
- Ground queries go through `heightfield.surface()` (matches the rendered mesh), never the raw `height()`.
- Dev: `#x,y,z,headingDeg` in the URL starts there and skips the title (heading 0 = north, 90 = east).
  `?debug` exposes `window.fly` (scene, renderer, tuning) for tooling.
- Forward is **-Z**. `yaw > 0` turns left, `pitch > 0` is nose up, `bank > 0` is right wing down.
  Object rotation order `'YXZ'`, `rotation.set(pitch, yaw, -bank)`.
- **Every feel constant goes in `tuning-defaults.json`** with a slider range in `tuning.ts`. Player settings
  (`ui/save.ts`) and quality presets (`applySettings` in `main.ts`) write into `tuning`, never around it.
- Frame-rate independent smoothing: `x += (target - x) * (1 - Math.exp(-rate * dt))`.
- No per-frame allocations in hot paths: reuse scratch vectors.
- Procedural world content uses `seeded(tuning.world.seed, '<system>')` from `random.ts` (never
  `Math.random()`). Audio noise, call timing and spark bursts are the exception: not world content.
- Lighting: world materials are `MeshLambertMaterial` (patched by `shading.ts`); objects placed on the
  terrain use `worldMaterial()`. Blender assets carry vertex colors (with baked AO) and no materials.
- Fog is global and custom (`fog.ts`). A material thins its own fog with `#define FOG_DENSITY_SCALE <expr>`.
  Unlit materials (MeshBasic, Points) must be tinted by the light themselves or they glow at night.
- Uniform values shared across materials are typed arrays or shared `{ value }` objects (three shares those
  by reference); write them once per frame.
- Systems don't import each other's internals; `main.ts` wires them.
- Code comments explain *why*, briefly.
- After changing `art/*.py`, run it and commit the regenerated files in `public/models/` with it.

## Performance budget

16 ms/frame on an average laptop. Readouts in the tuning panel (G): `fps` (real), `cpuMs`, `calls`, `ktris`.
Reference (high quality, low over Harbor Town): ~225 draw calls, ~1.4 M triangles. Main costs: vegetation
(LOD ranges in `vegetation` tuning), grass (density/radius), real-time shadows, post at pixel ratio 1.5.
Adaptive quality steps down from high → medium → low if flight stays under 40 fps (until the player picks one).

## Workflow

- Vertical slices; each ends playable. Commit when something works and looks right.
- Tune feel with sliders, not prompts: Export JSON from the panel, replace `src/tuning-defaults.json`.
- A visual pass must never silently change flight or camera feel: if a change touches `flight.ts`,
  `camera.ts` or tuning defaults, say so explicitly.
- Verify visually: the preview at `npm run build && npx vite preview` with Playwright screenshots (Chromium at
  `/opt/pw-browsers`, SwiftShader: slow, so start near what you test via the URL hash).

## Status and next ideas

Done: stylized rendering base, Blender asset pipeline, vegetation and grass, cumulus clouds with shadows,
villages/landmarks/boats, spirit bird, arcade flight with boost/mouse/currents/speed FX, collectibles,
HUD, menus, save, ES/EN, adaptive quality.

Ideas not done: mobile/touch controls, landmark-specific challenges (timed rings through the arch), day
cycle on by default with night-only secrets, more creature variety (skins unlocked by feathers), photo mode,
moving vegetation placement to a worker, soft depth fade where clouds meet terrain.

## Out of scope

Multiplayer, combat, infinite procedural world.
